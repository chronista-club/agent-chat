# 02. 共有 UI 部品の使い方

> **Status**: Draft — Codex の入力設定・送信待ちの列・画像添付を共有済み
> **Related**: VP design 74、GFP design 10

## 方針

`packages/chat/src/` の Solid 部品は値と操作を props で受け、store・transport（IPC / Unison）を持たない。
アプリごとに違う部分は slot で差し込む。Codex の入力設定では権限の選択欄が slot
（VP = Codex 本体の権限メニュー、GFP = 会話が持つ 4 段階）。

| export | 中身 |
|---|---|
| `@chronista-club/agent-chat/codex-settings` | `CodexSettingsControls`（モード・権限 slot・実効権限・model / effort・保存中 / エラー）、`CodexRuntimeControls`、`changeCodexSelection`、`codexModelOf` / `codexEffortOf` |
| `@chronista-club/agent-chat/codex-queue` | `CodexQueuePanel`（native queue の行・再開・編集・並べ替え・取り消し・再取得）。操作は `act({kind, …})` |
| `@chronista-club/agent-chat/images` | `createImageAttachments(enabled)`（添付の状態・`take` で同期判定・`attach`・`restore`・objectURL 解放）、`ImageAttachmentList`、`pickImageFiles` / `readImageFile` / `toWirePayload` |

class 名は `conversation-model-select` / `conversation-model-readonly` / `codex-queue*` / `conversation-attachment*`。
見た目は各アプリの CSS が当てる。画像の貼り付けは `take` の同期判定で `preventDefault` する（`await` の後では既定動作に負ける）。

## consumer の設定（開発中の file: 依存）

Bun の `file:` 依存は package のファイルを 1 つずつ symlink で置く。部品が `solid-js` を実行時に import するので、
実体の場所（この repo）から解決すると solid-js が見つからない。consumer の各ツールで **置かれた場所から解決** させる。

- tsconfig: `"preserveSymlinks": true`
- esbuild の各 `build()`（bundle・DOM テスト）: `preserveSymlinks: true`
- vitest: `resolve.preserveSymlinks: true`

この package に solid-js を入れない（peerDependency）。2 つ読み込まれると Solid のリアクティブ状態が壊れる。
npm で配布した後はファイルが実体で置かれるので、この設定が無くても解決できる。
